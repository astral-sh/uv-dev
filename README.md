# activate.fish runs commands from a path or prompt

Issue: astral-sh/uv#23060

Classification: duplicate

Canonical discussion: astral-sh/uv#19812 (open draft pull request)

## Summary

The reporter describes command execution while sourcing a fish activation script generated by uv 0.13.6 on Fedora Linux. The supplied reproduction passes a single quote and additional fish statements through `uv venv --prompt`, then sources `venv/bin/activate.fish`. The expected behavior is to retain that input as literal prompt text. The title also raises environment paths, but the issue body supplies only a custom-prompt reproduction.

Open draft astral-sh/uv#19812 already tracks the fish prompt bug. Historical path-escaping fixes and the companion Bash/Zsh report provide context; fish path handling still needs separate verification.

The reporter cites virtualenv commit 3bddeaf8d02c3ee7f576503efb082f8f494cfcab and CVE-2026-113732, and says Astral previously treated this as a regular correctness bug under uv's threat model. The classification here does not independently assign a vulnerability designation.

## Draft response

Your --prompt example matches the bug already being addressed in the open draft astral-sh/uv#19812. The current generator inserts the prompt directly into fish single-quoted strings; that PR adds fish-specific escaping for quotes and backslashes, but has not merged. Please continue the discussion there with this reproduction and the upstream path case. The path case needs separate coverage because the PR currently leaves environment-path escaping unchanged.

The canonical PR was opened on 2026-06-11; this issue was opened on 2026-11-02. It was therefore not created in response to this report. It remains a draft, has no reviews or inline review comments, and has not merged. Its existing comment is a test-inventory report, not confirmation that a fix has shipped.

Centralizing the prompt report does not establish that every path variant is resolved.

## Supporting evidence

### Report decomposition

- Observable symptom: sourcing `activate.fish` executes statements supplied as prompt data. The trigger is an explicit `--prompt` containing a single quote that terminates the generated literal.
- Separate title claim: an environment path can also be interpreted as commands. The cited upstream change exercises backslash-plus-quote paths; the issue itself does not include a path-only reproducer.
- Subsystem and expected capability: `uv venv`, activation-template substitution, and fish string-literal quoting must preserve paths and prompts as data.
- Exact identifiers: `activate.fish`, `VIRTUAL_PROMPT`, `VIRTUAL_ENV_DIR`, `VIRTUAL_ENV_PROMPT`, and CVE-2026-113732. Fedora and uv 0.13.6 identify the reported environment, not a proven platform restriction. No error fragment is reported.

### Source and release checks

The checked-out source and the source fetched from the uv 0.13.6 tag agree:

- `crates/uv-virtualenv/src/virtualenv.rs:511`–`517` special-cases Xonsh prompt serialization but borrows the raw prompt for fish. At line 536, it replaces the prompt placeholder with that value.
- `crates/uv-virtualenv/src/activator/activate.fish:97`–`98` places the placeholder inside single quotes in both the nonempty check and the assignment to `VIRTUAL_ENV_PROMPT`. This confirms the reported prompt-quoting defect independently of the CVE reference.
- `crates/uv-virtualenv/src/virtualenv.rs:494`–`508` uses `escape_posix_for_single_quotes` for non-relocatable fish environment paths. `crates/uv-shell/src/shlex.rs:32`–`37` escapes apostrophes by concatenating POSIX quoted strings, but does not escape backslashes.
- `crates/uv-virtualenv/src/activator/activate.fish:82` embeds the environment path; line 100 derives the default prompt with `basename` at runtime. Therefore the ordinary default prompt should not be conflated with the explicit raw `--prompt` substitution.
- The diff of astral-sh/uv#19812 adds `PromptQuoting::Fish`, escapes backslashes and single quotes, and removes the redundant surrounding quotes from both fish prompt placeholders. Its environment-path branch still uses the POSIX helper.
- The uv 0.5.3 release notes identify astral-sh/uv#8984 as the apostrophe-path fix. Its diff modifies `VIRTUAL_ENV_DIR`, not `VIRTUAL_PROMPT`. The maintainer statement in astral-sh/uv#9424 concerns that historical path fix; it is not evidence that prompt escaping was fixed and later regressed.

The upstream commit was inspected directly:
https://github.com/pypa/virtualenv/commit/3bddeaf8d02c3ee7f576503efb082f8f494cfcab

It replaces inherited POSIX quoting with fish-specific escaping of backslashes and single quotes and adds separate prompt and directory-name tests. This supports investigating the distinct path case in uv, but does not substitute for executing that case against uv.
