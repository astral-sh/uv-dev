# standalone installer - UV_ASTRAL_MIRROR_URL is not used when set

Issue: astral-sh/uv#22267

Classification: duplicate

## Summary

The reporter runs uv 0.12.23 on Linux x86_64 and Windows 11 x64. Both standalone installers ignore `UV_ASTRAL_MIRROR_URL` when choosing artifact URLs. Their organization permits a proxy repository for `releases.astral.sh` but forbids a GitHub mirror. They need installation instructions that do not require users to know the current version and want installation and self-update to share the mirror configuration. They also ask where the generated installers' source is maintained.

astral-sh/uv#18525 contains the exact unresolved installer discussion; astral-sh/uv#19206 implemented mirror support inside uv. astral-sh/uv#22264 concerns a separate logging defect.

## Draft response

The 0.12.23 standalone scripts do omit `UV_ASTRAL_MIRROR_URL`. The same gap and version-independent installation requirement are discussed in the May 18–19 comments on astral-sh/uv#18525. That issue was closed after astral-sh/uv#19206 added mirror support inside uv; direct installer support remained unimplemented. `uv self update` already passes a mirror-specific `UV_DOWNLOAD_URL` to the installer.

Please continue the installer discussion in astral-sh/uv#18525 so the remaining work stays together. For the source, these scripts are generated by cargo-dist: the templates are `installer.sh.j2` and `installer.ps1.j2` under https://github.com/axodotdev/cargo-dist/tree/main/cargo-dist/templates/installer.

## Supporting evidence

### Published installers and generation

Read the published 0.12.23 scripts without executing them:

- Shell: https://releases.astral.sh/github/uv/releases/download/0.12.23/uv-installer.sh, lines 28–40.
- PowerShell: https://releases.astral.sh/github/uv/releases/download/0.12.23/uv-installer.ps1, lines 40–52.

Both select URLs in this order: `UV_DOWNLOAD_URL`, `INSTALLER_DOWNLOAD_URL`, `UV_INSTALLER_GHE_BASE_URL`, `UV_INSTALLER_GITHUB_BASE_URL`, then the default Astral and GitHub URLs. Neither selection block reads `UV_ASTRAL_MIRROR_URL`. The GitHub base overrides append `/astral-sh/uv/releases/download/0.12.23`; the default Astral URL uses `/github/uv/releases/download/0.12.23`. This confirms the reported omission and explains why the existing base overrides do not directly address an Astral mirror's layout.

`dist-workspace.toml` specifies cargo-dist 0.32.0, shell and PowerShell installers, and the Astral simple-download URL. `.github/workflows/release.yml:229` generates global artifacts with `dist build`. The matching upstream template selection logic is in:

- https://github.com/axodotdev/cargo-dist/blob/main/cargo-dist/templates/installer/installer.sh.j2
- https://github.com/axodotdev/cargo-dist/blob/main/cargo-dist/templates/installer/installer.ps1.j2

### Existing implementation and chronology

astral-sh/uv#19206 merged on May 12, 2026. Its changed files cover Rust mirror configuration and consumers, not the standalone installer templates. `crates/uv-static/src/env_vars.rs:564` documents the mirror override and marks its introduction as 0.11.14. A configured mirror disables GitHub fallback inside uv.

On May 18, the follow-up in astral-sh/uv#18525 showed the same missing installer branch in 0.11.14. The maintainer noted that each installer embeds a particular version and its binary hashes. On May 19, the requester clarified that a mirrored latest-installer URL should work with a stable mirror base, without separately determining that embedded version. This is the same user-visible requirement as the new report; there is no evidence that direct installer handling was subsequently implemented and then regressed.

`crates/uv/src/commands/self_update.rs:42` constructs the version-specific artifact URL from the configured Astral mirror. `execute_official_installer` passes it as `UV_DOWNLOAD_URL` at line 545. The existing test `test_execute_official_installer_sets_download_url_for_astral_mirror` covers that handoff. Thus the source confirms support when the installer is invoked by self-update; the reported omission concerns direct standalone execution.

### Other candidates and important differences

astral-sh/uv#22264 explicitly describes a logging-only problem and acknowledges correct mirror downloads. The open response PR astral-sh/uv#22373 changes the self-update success-message URL, not standalone URL selection. Neither is a duplicate of this report.

astral-sh/uv#22265 concerns PowerShell ignoring `NO_PROXY`; it shares the reporter and network environment but has a different mechanism.

Historical discussions astral-sh/uv#9134, astral-sh/uv#16519, and astral-sh/uv#17255 concern internal mirror layouts, GitHub API metadata, and version discovery during self-update. The completed tracking issue astral-sh/uv#18503 concerns using the default Astral endpoint, not overriding it.
