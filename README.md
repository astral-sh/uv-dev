# virtualenv activation scripts run code from a path that contains a placeholder name

Issue: astral-sh/uv#23390

Classification: duplicate

## Summary

The reporter describes unexpected shell evaluation when sourcing `bin/activate` generated by `uv venv` on uv 0.13.7, both with a placeholder-looking directory name and with an explicit `--prompt`. The expected behavior is for both inputs to remain literal.

astral-sh/uv#23278 already tracks activation-template substitutions rewriting inserted values. The explicit prompt case also overlaps with the separate shell-quoting bug in astral-sh/uv#23058 and its proposed fix in astral-sh/uv#23155.

## Draft response

Please follow astral-sh/uv#23278 for the template-rendering fix. It makes the renderer replace only placeholders in the original template, so a marker in your path or prompt stays literal. uv 0.13.7 does not use `__VIRTUAL_NAME__` as a marker, so the source does not confirm that exact path example. Your `--prompt` example also overlaps with astral-sh/uv#23058: the generated script can interpret the prompt as shell syntax even without a template marker.

## Classification

The open astral-sh/uv#23278 predates this report and covers the same underlying template defect: a later replacement can rewrite text inserted by an earlier one. It is not a response to this issue or a previously shipped fix. The explicit prompt's separate shell-quoting defect is already tracked in astral-sh/uv#23058.

A uv maintainer confirmed that this report is outside uv's security scope and will follow ordinary issue triage. The rationale is that control over process environment variables can already permit code execution. This decision does not confirm either reproduction or change the duplicate classification.

## Related

- astral-sh/uv#23278 — **Open.** Canonical for the template defect. Replaces the chained substitutions with a single pass over the original template and adds an activation test that checks literal values for both the environment path and the prompt.
- astral-sh/uv#23058 — **Open.** Tracks shell interpretation of activation prompts. It overlaps with the explicit `--prompt` example, but that behavior does not require a template marker or a second replacement pass.
- astral-sh/uv#23155 — **Open.** Proposes quoting explicit prompts as shell literals for astral-sh/uv#23058 and tests sourcing with a custom prompt. It does not stop later template substitutions from rewriting an inserted path.

## Supporting evidence

- The tagged uv 0.13.7 source and the checkout both apply successive replacements in `crates/uv-virtualenv/src/virtualenv.rs:536` (checkout line). An inserted value containing a marker processed later can therefore be changed. uv uses markers such as `{{ VIRTUAL_PROMPT }}`, not upstream virtualenv's `__VIRTUAL_NAME__`. This confirms the rendering defect, not the reported command execution from that exact path. The upstream advisory GHSA-8rjx-v5ww-45pp lists the `virtualenv` package, not uv.
- In the POSIX activator, the environment path is placed in a single-quoted assignment, but the custom prompt is inserted into double-quoted shell expressions in `crates/uv-virtualenv/src/activator/activate:106`. The explicit prompt can therefore be interpreted when the script is sourced independently of placeholder replacement. No command-execution example was run.
- uv 0.13.7 was published on November 3, 2026. The template PR opened on November 17, 2026, before the report on November 24, 2026, and has not merged. The nearby merged Windows path fix does not change this renderer behavior.
