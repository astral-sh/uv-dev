# HTTP credentials

uv uses HTTP credentials to query private package registries.

uv checks these credential sources in order:

- The URL, e.g., `https://<user>:<password>@<hostname>/...`
- A [netrc](#netrc-files) configuration file
- The uv credentials store
- A [keyring provider](#keyring-providers) (off by default)

uv uses these credentials for hosts in the following settings and requirements:

- `[index]`
- `index-url`
- `extra-index-url`
- `find-links`
- `package @ https://...`

## netrc files

[`.netrc`](https://everything.curl.dev/usingcurl/netrc) files store credentials in a standard
plaintext format.

uv always reads credentials from `.netrc` files. It uses the path in the `NETRC` environment
variable, or `~/.netrc` if that variable is not set.

## The uv credentials store

The [`uv auth` commands](./cli.md) read and write credentials in the uv credentials store.

uv saves credentials in a plaintext file in its state directory. On Unix, this file is usually
`~/.local/share/uv/credentials/credentials.toml`. Do not edit this file manually.

!!! note

    Secure system-native storage is in [preview](../preview.md). This experimental feature remains
    under active development. It will become the default storage mechanism in the future.

    When this feature is enabled, uv uses the operating system's native secret storage. On macOS, it
    uses Keychain Services. On Windows, it uses Windows Credential Manager. On Linux, it uses the
    DBus-based Secret Service API.

    uv retrieves only credentials that it added to the native store. It does not retrieve
    credentials that other applications saved.

    Set `UV_PREVIEW_FEATURES=native-auth` to use this storage mechanism.

## Keyring providers

A keyring provider retrieves credentials through an interface that matches the
[keyring](https://github.com/jaraco/keyring) Python package. `pip` also supports this interface.

The "subprocess" keyring provider runs the `keyring` command to fetch credentials. uv does not
support other keyring provider types.

Set `--keyring-provider subprocess`, `UV_KEYRING_PROVIDER=subprocess`, or
`tool.uv.keyring-provider = "subprocess"` to use the provider.

## Persistence of credentials

uv caches credentials for an index URL or network location during the current command. A network
location consists of a scheme, host, and port. uv reuses those credentials for other requests to the
same location. It does not cache credentials between commands.

`uv add` _does not_ save index credentials in `pyproject.toml` or `uv.lock`. These files often
appear in source control and distributions, where credentials can become public. However, uv _does_
save credentials in direct URLs, such as `package @ https://username:password:example.com/foo.whl`.
There is currently no other way to provide credentials for these URLs.

If `uv add` receives credentials in an index URL, later commands might not have those credentials.
These commands can then fail to fetch dependencies from private indexes. See the
[index authentication documentation](../indexes.md#authentication) to configure persistent index
authentication.
